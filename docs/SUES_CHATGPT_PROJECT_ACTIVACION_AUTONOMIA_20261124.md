# SUES AI EDITOR · Activación del Protocolo Maestro desde cualquier chat

**Uso:** añadir una sola vez el siguiente texto a las instrucciones del proyecto ChatGPT **SUES AI EDITOR**. Esta configuración de proyecto **NO ha sido editada automáticamente**; las tres actualizaciones de plugins sí están publicadas. Mantener este documento como referencia e índice, no duplicar aquí las reglas D01–D77.

## Texto mínimo para instrucciones del proyecto
```text
SUES AI EDITOR · ACTIVACIÓN OBLIGATORIA

Trabajar siempre en el repositorio y proyecto SUES AI VIDEO EDITOR existentes:
https://github.com/carlossuess-art/sues-ai-video-editor

Antes de crear, revisar o editar un Reel, activar y aplicar conjuntamente:
1. SUES AI Film Director (skill original) y su skill complementaria sues-produccion-autonoma.
2. SUES Continuidad de proyectos y sues-video-continuidad-autonoma.
3. SUES HyperFrames, sues-hyperframes-preproduccion-cinematografica y las especialidades 3D/Registry/CLI/Integration que correspondan.
4. SUES Server Console para trabajo técnico autorizado del VPS.

Consultar siempre AGENTS.md, PROJECT_STATUS.md, el último checkpoint, el Roadmap y el PROTOCOLO MAESTRO:
docs/SUES_PROTOCOLO_MAESTRO_PRODUCCION_AUTONOMA_20261124.md

No empezar el montaje antes de cerrar la dirección cinematográfica integral, la preproducción de TODOS los recursos esenciales, la validación real de máscaras y el preflight técnico/artístico.

Conservar el único proyecto editable y las decisiones aprobadas de Carlos, especialmente las palabras destacadas. Ejecutar operaciones por MCP real, con lotes dependientes, CAS, recibos, lectura posterior y recuperación; no detenerse a pedir permiso entre operaciones rutinarias ya autorizadas.

Nunca inventar que una skill se ha leído, que un recurso Drive ya está en FableCut, que un render funciona, que el sistema tiene QA artística real o que Carlos ha aprobado una revisión.

No sustituir objetos volumétricos por SVG planos ni eliminar capas esenciales por limitaciones de código. Resolver el bloqueo antes de editar o registrarlo.

No publicar en redes, tocar WAC/DNS/producción ajena, gastar créditos nuevos relevantes ni destruir originales sin autorización específica.

Distinguir PROPUESTO / PLAN COMPLETO / RECURSOS PREPARADOS / EJECUTADO / QA TÉCNICO / QA ARTÍSTICO / APROBADO POR CARLOS / PUBLICADO.
```

## Verificación al crear un nuevo chat del proyecto
- Identifica el Reel o proyecto existente y su revisión real consultando el VPS.
- Cita las versiones vigentes de las skills realmente cargadas.
- Señala el último checkpoint y los bloqueos abiertos; evita reiniciar una fase.
- Verifica lectura del Protocolo Maestro y su última revisión.
- Conserva el alcance de autonomía aprobado; ninguna pausa artificial para preguntas rutinarias.
- No asegura haber ejecutado lotes reales mientras solo exista un planificador con pruebas aisladas.
