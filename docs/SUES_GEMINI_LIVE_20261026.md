# Gemini in the existing editor

Production-based integration: explicit Gemini planning with video/audio and the native asset catalogue; OpenAI remains disabled in the UI. Planning runs in the background, persists its result and draft, and resumes status polling after reload. A plan is validated before execution in another version. No automatic provider fallback or paid retry is introduced.

Private media stay outside Git. A separately verified reviewed export was imported with its original audit and explicit import provenance; it is not labelled as re-rendered by this runtime. Existing source analysis is reused. Native assets with third-party marks or demonstration text are filtered out of the cloud catalogue.

The renderer receives the already verified tracked-frame duration correction, literal lower hero labels and safe layout selection, without deploying experimental foreground model modules.

Validation: 32 focused tests; full Docker suite 347/350, with two stale expectations corrected and revalidated (4/4) and the Git-only case validated on host (2/2). Browser desktop/mobile pass both scene-plan controls and the Edit with Gemini button, including reload during analysis, persisted proposal, no overflow and no JS errors. Browser provider responses are simulated; live provider validation and deployment evidence are recorded separately.

Existing quota is retained: 512 native assets / 2 GiB total / 40 MiB per asset. No free multi-track timeline or automatic execution of Adobe/CapCut templates is claimed.
